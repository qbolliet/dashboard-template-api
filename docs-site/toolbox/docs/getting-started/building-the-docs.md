# Building the Documentation

The documentation is **two static Docusaurus sites** built from the same `docs-site/`
package (one `package.json`, one lockfile, one `node_modules`), each with its own config:

| Site           | Config                         | Base URL                           | Content                                                                                                                                          |
| -------------- | ------------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **API & Data** | `docusaurus.config.api.ts`     | `/dashboard-template-api/`         | API guide, bulk export, TypeScript client, data dictionary (generated from the API), GraphQL reference (generated from the SDL), Schema Explorer |
| **Toolbox**    | `docusaurus.config.toolbox.ts` | `/dashboard-template-api/toolbox/` | Getting started, deployment, configuration, architecture, versioning policy, code reference (generated by TypeDoc)                               |

GitHub Pages serves one artifact per repository: the two builds are merged into
`docs-site/build/site/` (API & Data at the root, Toolbox under `toolbox/`).

```
docs-site/
├── docusaurus.config.api.ts · docusaurus.config.toolbox.ts · site-shared.ts
├── api/        docs/ · pages/ (Voyager) · graphql-api/ (generated) · data-dictionary/ (generated)
├── toolbox/    docs/ · code-reference/ (generated)
├── static/     schema.graphql · schema.json (generated, API site only)
├── templates/  landing pages of the generated sections
└── scripts/    generation and assembly scripts
```

## Prerequisites

| Tool                       | Notes                                                      |
| -------------------------- | ---------------------------------------------------------- |
| Node.js ≥ 20               | Required by Docusaurus, TypeDoc and the generators         |
| npm dependencies installed | `npm install` at repo root + `npm install` in `docs-site/` |

```bash
npm install
npm --prefix docs-site install
```

## Documentation scripts

All documentation scripts are defined in the root `package.json` and run from the repo root.

| Script                         | What it does                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `npm run docs:typedoc`         | Generates the Code Reference pages from TypeScript source into `docs-site/toolbox/code-reference/`       |
| `npm run docs:schema`          | Regenerates `schema.graphql`, then derives `docs-site/static/schema.graphql` and `schema.json` (Voyager) |
| `npm run docs:graphql`         | Generates the GraphQL reference pages from the SDL into `docs-site/api/graphql-api/`                     |
| `npm run docs:dictionary`      | Generates the data dictionary into `docs-site/api/data-dictionary/` from the API at `API_URL`            |
| `npm run docs:dictionary:test` | Same, against a temporary API started on the test catalogs                                               |
| `npm run docs:build:toolbox`   | TypeDoc, then builds the Toolbox site into `docs-site/build/toolbox/`                                    |
| `npm run docs:build:api`       | SDL, GraphQL reference, data dictionary, then builds the API & Data site into `docs-site/build/api/`     |
| `npm run docs:build`           | Both sites, then merges them into `docs-site/build/site/`                                                |
| `npm run docs:build:test-api`  | `docs:build` with the API started on the test catalogs (data dictionary of the test data)                |

## Data dictionary

The data dictionary is generated from a **running API** (`getCatalogs`, `getDatasetInfo`,
`getCatalogSchema`): one page per catalog and schema.

```bash
# The API is running (npm run dev)
API_URL=http://localhost:4000/graphql npm run docs:dictionary

# No API to hand: start one on the test catalogs for the duration of the command
npm run test:setup
npm run docs:dictionary:test
```

`API_URL` defaults to `http://localhost:4000/graphql`. The build **never fails** because
of the dictionary: when the API is unreachable the generator logs a warning and keeps
the pages of the previous run; a schema that cannot be described (unsupported version,
missing `dataset_metadata`) is skipped with a warning and the others are written. The
pages are rendered aside and only replace the previous ones once complete.

In CI (`.github/workflows/docs.yml`), the repository variable `API_URL` points at the
deployed API; when it is not set, the workflow builds against the test catalogs.

## Build the full documentation (production)

```bash
# From the repo root
npm run docs:build
```

Serve the merged output locally to preview the production build:

```bash
npm --prefix docs-site run serve
# → http://localhost:3000/dashboard-template-api/           (API & Data)
# → http://localhost:3000/dashboard-template-api/toolbox/   (Toolbox)
```

## Development server (live reload)

Generate the auto-built sections of the site you edit, then start its dev server. The
two sites share the same `.docusaurus/` cache directory: run **one dev server at a time**
and build the sites one after the other.

```bash
# Toolbox
npm run docs:typedoc
node docs-site/scripts/copy-doc-templates.mjs toolbox
npm --prefix docs-site run start:toolbox     # → http://localhost:3001/dashboard-template-api/toolbox/

# API & Data
npm run docs:schema
npm run docs:graphql
npm run docs:dictionary
node docs-site/scripts/copy-doc-templates.mjs api
npm --prefix docs-site run start:api         # → http://localhost:3000/dashboard-template-api/
```

:::note
The generated sections (Code Reference, GraphQL API, Data Dictionary) require their
generation step to be run at least once before they appear. Docusaurus cannot route or
check links between the two builds: a link from one site to the other is an absolute URL
(`https://qbolliet.github.io/dashboard-template-api/...`), so on a local preview it leads to
the published site.
:::

## Docusaurus CLI reference

These commands run from the `docs-site/` directory (prefix with `npm --prefix docs-site run`):

| Command                       | Description                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------- |
| `start:api` / `start:toolbox` | Start the dev server of one site with live reload                                                 |
| `build:api` / `build:toolbox` | Build one site into `build/api` or `build/toolbox`                                                |
| `serve`                       | Serve `build/site/` locally                                                                       |
| `graphql-to-doc`              | Generate the GraphQL reference (run through `npm run docs:graphql`, which selects the API config) |
| `clear`                       | Clear the Docusaurus cache (`.docusaurus/` and `build/`)                                          |
